# model/: TLA+ models of the P2 design

[`Epoch.tla`](Epoch.tla) states the anti-rollback epoch of [§3.2 to §3.5](../docs/03-measured-boot-sealing.md#34-anti-rollback-epoch-sr-0103) only as generic TPM 2.0 commands on the epoch NV index: `NV_DefineSpace` (any attributes from a small set, owner auth), `NV_UndefineSpace` (owner auth, refused with `POLICY_DELETE`), `NV_SetBits`, `StartAuthSession`, `PolicyNV`, `PolicyAuthorize` and `Unseal`, plus the legitimate `Commit(e)` of §3.5 step 4. No action describes an attack. Two releases, at epochs 1 and 2, have approved policies that bind the index's name at provisioning. `NoOldReleaseUnseals`: no release older than the committed epoch obtains the keys. `EpochMonotonic`: the epoch never decreases, that is, whenever the epoch index is defined and written, as `PolicyNV` needs, its epoch (highest set bit) is at least the committed one, and at least its epoch in the previous state if it was then defined and written.

**Result, in this model.** On [`Epoch.cfg`](Epoch.cfg), today's recorded design (the attributes of `tests/ve07/provision.py`, empty owner auth), TLC finds `NoOldReleaseUnseals` violated in eight steps: `Commit(2)`, `NV_UndefineSpace`, `NV_DefineSpace` with the same attributes, `NV_SetBits({})`, then a session passes release 1's `PolicyNV`, `PolicyAuthorize` and `Unseal`. That is audit finding A-01 ([§6.6](../docs/06-verification.md#66-limits-of-the-ci-evidence)), which the model was not told about. TLC stops at the first violation, so [`EpochMonotonic.cfg`](EpochMonotonic.cfg) checks `EpochMonotonic` on the same design: it is violated in four steps, `Commit(1)`, `NV_UndefineSpace`, `NV_DefineSpace` (any attributes), `NV_SetBits({})`, which leave a written index at epoch 0. With owner auth set, or with `policy_delete` in `ProvAttrs`, TLC finds neither property violated in this model: [`FixOwnerAuth.cfg`](FixOwnerAuth.cfg) and [`FixPolicyDelete.cfg`](FixPolicyDelete.cfg), two of the candidate fixes, with their witnesses, that [`docs/model-fix-options.md`](../docs/model-fix-options.md) sets out for the owner's decision.

[`Boot.tla`](Boot.tla) adds §3.1 and §3.3 to it, through `INSTANCE Epoch`. PCRs 0, 1, 8 and 9 of the SHA-256 bank hold measurement sequences, and `Extend(p, v)` is one command for whichever stage runs. The stages run in order, ROM → U-Boot → kernel → initramfs → userspace, each issuing its program's commands: U-Boot extends the release's measurement into each PCR; the initramfs runs `p2-unseal`: `StartAuthSession`, `PolicyPCR`, `PolicyNV` (release 2's operand), `PolicyAuthorize` and `Unseal`, then, if `CapAfterUnseal`, the cap of step 4, an `Extend` of each PCR with the cap event. The attacker runs in userspace and may issue any of these commands with any arguments; `Commit` runs there too. `Reboot`, a power cycle, may come at any time: the TPM resets, NV persists, and the CC boots from the ROM. `TPMReset`, the TPM alone, is the attacker's only if its `Tier` allows it. No action describes an attack. `OnlyInitramfsObtainsKeys`: keys are obtained only while the approved initramfs runs; stages run only signed code (SR-005). `NoOldReleaseUnseals` and `EpochMonotonic` are Epoch's, checked here too.

**Result, in this model.** On [`Boot.cfg`](Boot.cfg), today's recorded design with the cap and a `"physical"` attacker, TLC finds `OnlyInitramfsObtainsKeys` violated in 27 steps: the approved boot unseals and caps, then in userspace `TPMReset`, `Extend` of each PCR with the release's measurement, and a new session passes `PolicyPCR`, `PolicyNV`, `PolicyAuthorize` and `Unseal`. That is the reset-and-replay path of A2-02 and THR-034's residual risk. With a `"root"` attacker, [`BootRoot.cfg`](BootRoot.cfg) passes all three properties, and [`BootRootWitness.cfg`](BootRootWitness.cfg) shows the initramfs's unseal reachable on the same constants. The control [`BootNoCap.cfg`](BootNoCap.cfg) leaves the cap out, as TC-05's control build does: root in userspace unseals again with no extend, in 18 steps. That is A-02 as the audit wrote it, before DD2-18, which the model was not told about.

**Measurements as symbols.** A PCR holds the sequence of what was extended into it since the last TPM reset, not a hash. Extending is one-way, and H is taken as collision-free, as for names, so a PCR equals its approved value exactly when its sequence does, and once a sequence is no prefix of the approved one it never becomes one: every such sequence is one value, `<<"unapproved">>`. U-Boot's events into one PCR are one symbol, `"release"`, since `PolicyPCR` reads only the final value and the events are not secret: the release artifacts and the event log predict them. The values an attacker may extend are `"release"` and the cap event, which stands for every other digest. Both releases are approved for the same PCRs, so only `PolicyNV` separates them, as in the A-01 replay. `PolicyPCR`'s part of the session digest is `pcrPolicy`: `"approved"` only if it runs first in the session on the approved PCRs, else `"other"`, and `PolicyAuthorize` needs `"approved"`. The TPM also refuses a session whose PCRs changed after `PolicyPCR`; the model leaves that check out, which only gives the attacker more.

**Stage as one variable.** One stage runs at a time, and `pc` is its next command, so the stages share the TPM as one program does, and no stage runs again until a `Reboot`. Each command of the initramfs runs only if the TPM accepts it. In this model it always does (the PCRs are U-Boot's, release 2 is the newest; with `ENABLED`, TLC finds the next command enabled in every reachable state, for both tiers, a local check, not a configuration), so `p2-unseal`'s refusal path, after which it still caps, is not modeled; the witness shows the unseal is reached. A warm reboot, which keeps the PCRs under DD2-17, is not modeled: the next boot's measurements land on old values, which match no policy, and an attacker in userspace can extend any PCR anyway.

**Tiers, and who can reset the TPM.** `data/p1/threats.csv` records no attacker tiers (P1's A-08 has three, outside the snapshot), so the model uses a minimal split: `"root"`, code running as root on the CC (THR-010), and `"physical"`, a captured CC (THR-034, A-08 tier 2). Both act only in userspace. Only `"physical"` may reset the TPM alone: DD2-17 leaves its reset pin on the module's pull-up, so no software can drive it, and a power cycle resets the CC with it. With the board in hand the pin can be driven, which A2-02 assumes cannot happen and is not yet checked on the module. `TPM2_Clear` is not modeled: it replaces the storage seed, so it can deny the keys but not release them. Boot has none of Epoch's NV commands, so A-01 cannot mask what stages add, and `NoOldReleaseUnseals` here says only that they add no older release.

**Finite.** PCR values are `<<>>`, `<<"release">>` or `<<"unapproved">>`, `pc` is bounded by the longest program, the session, epoch and `released` are Epoch's, and `unsealedIn` is a set of stages, so the state space is finite: 30,212 states with a `"physical"` attacker and 214 with `"root"`, each configuration checked in seconds.

**Run.** `python3 model/ci.py` runs TLC on every entry of [`configs.json`](configs.json) and fails unless each outcome is the `expect`ed one; TLC's logs and JSON counterexamples go to `build/model/` (`--out` to change). `python3 model/run_tlc.py SPEC CFG TRACE` runs one. Both need Java 11 or later (`$JAVA_HOME`, or `java` on the PATH), fetch the jar named in [`tla2tools.pin`](tla2tools.pin) to `.cache/tla/` and refuse it unless its SHA-256 matches. A `pass` entry means little if a modeling error makes `Unseal` unreachable, so each one needs a witness entry on the same constants, such as an invariant `<<2, 2>> \notin released` expected violated, showing that the legitimate release still unseals. Replay tests added under `tests/model/` run after TLC, with `P2_MODEL_TRACES` set to the output directory. `-t .` imports them as `tests.model.*`, so that directory needs an `__init__.py`; it also puts them in the `validate` job's `discover -s tests`, so a test that reads traces must skip unless `P2_MODEL_TRACES` is set, and one that needs a tool must skip without it there, as the replay below does. A trace is a JSON list of states, each mapping variable names to values, without action names. CI: [`model.yml`](../.github/workflows/model.yml). **The pin.** Only TLA+'s master builds have `-dumpTrace json`; 1.7.4, the latest stable release, has no `-dumpTrace`. The `v1.8.0` and `rolling` pre-release assets are rebuilt from master, so their SHA-256 changes and a CI cache miss would turn the job red, and the Sonatype snapshot jar lacks its dependencies. The pin is the nightly build of commit `1a92ec7` (2023-09-15), whose URL names that one build and which is served unchanged since 2023-09-25. Newer builds also name each step's action in the trace. To use one, host it at a URL that names one build, write its SHA-256 and `X-Git-Revision` (`unzip -p tla2tools.jar META-INF/MANIFEST.MF`) to the pin, and run `python3 model/ci.py`. Every entry must keep its `expect`ed outcome; if one does not, review the new build before changing `configs.json`.

## Replay

[`trace_to_tpm2.py`](trace_to_tpm2.py) `TRACE` translates a TLC JSON counterexample of `Epoch.tla` into tpm2-tools 5.6 commands and prints them as JSON, one entry per step: the state it reaches, the action and its arguments, and the argv lists. The pinned TLC build names no actions, so each step's action is the one whose changes to the variables match the step's. A step that no action explains, an action without a mapping, a `PolicyNV` whose operand the trace does not keep (its digest is `Other`) and a trace without a step exit with an error naming the state or the action; none is skipped. `{placeholders}` name what the harness supplies; `session.ctx`, `kpol.ctx`, `kpol.name`, `ticket.bin` and `sealed.ctx` are working files in the directory the commands run in.

| Action (`Epoch.tla`) | tpm2-tools commands |
|---|---|
| `NV_DefineSpace(i, a, p)` | `tpm2_nvdefine {epoch_index} -C o -s` size `-a nt=bits\|`*a*, and `-L {other_policy}` if *p* is `"other"` |
| `NV_UndefineSpace(i)` | `tpm2_nvundefine {epoch_index} -C o` |
| `NV_SetBits(i, b)` | `tpm2_nvsetbits {epoch_index} -i` mask of the bits the step sets, `-C o` if the index has `ownerwrite` and owner auth is empty, else `-C {epoch_index}` (`authwrite`) |
| `StartAuthSession` | `tpm2_flushcontext -s` if a session is open; `tpm2_startauthsession --policy-session` |
| `PolicyNV(i, b)` | `tpm2_policypcr -l {pcr_selection}` (PCR stages are not in the model); `tpm2_policynv -i {operand_E} {epoch_index} bc`, where *b* = {*E*+1 .. `MaxEpoch`} is release *E*'s operand, which in the TPM sets every bit above *E* |
| `PolicyAuthorize` | `tpm2_loadexternal -u {kpol_pub}`, `tpm2_verifysignature -m {signed_E} -s {policy_dir_E}/approved.sig`, `tpm2_flushcontext -t`, `tpm2_policyauthorize -i {policy_dir_E}/approved -q {policy_ref}`, for *E* = `via` |
| `Unseal` | `tpm2_load -C {parent} -u {sealed_pub} -r {sealed_priv}`, `tpm2_unseal -p session:session.ctx`, `tpm2_flushcontext -t` and `-s` |
| `Commit(e)` | `tpm2_flushcontext -s` if a session is open (the commit runs in a later boot); `tpm2_nvsetbits {epoch_index} -C o -i` bit *e*, with `-P {owner_auth}` if owner auth is set |
| `Extend(p, v)` (`Boot.tla`) | `"release"`: `tpm2_pcrextend` *p*`:sha256={release_`*p*`}`; the cap event: `tpm2_pcrevent` *p* `{cap_event}`, `TPM2_PCR_Event` as `p2-unseal` does |
| `PolicyPCR`, `PolicyNV(b)` (`Boot.tla`) | `tpm2_policypcr -l {pcr_selection}`; `tpm2_policynv` alone, as above |
| `Reboot`, `TPMReset` (`Boot.tla`) | `tpm2_shutdown -c`, as Linux does on reboot, so the DA counter does not move; `swtpm_ioctl --tcp {swtpm_ctrl} -i` (`_TPM_Init`); `tpm2_startup -c` |
| `Handover` (`Boot.tla`) | none: the next stage starts |

Every action has a command; only `Handover` is model-only. `tests/test_model_tools.py` checks that every action of `Next` has a mapping. `{signed_E}` is release *E*'s `approved` followed by the policyRef, which `{policy_ref}` holds, and `{operand_E}` is `tools/approve_policy.py`'s `epoch_operand(E)`.

[`tests/model/test_replay_a01.py`](../tests/model/test_replay_a01.py) translates [`fixtures/a01-trace.json`](../tests/model/fixtures/a01-trace.json), TLC's `Epoch.cfg` counterexample as written by the pinned build, checks the result against the replay written by hand (`A01`), and runs it on swtpm 0.7.3 with the harness of [`tests/ve07/provision.py`](../tests/ve07/provision.py) and a K-CC-POL generated in a temporary directory. Under `model/ci.py` it also checks that the trace TLC writes on that run still translates to `A01`, so the fixture cannot go stale unnoticed. After `Commit(2)` it first checks the baseline of TC-08: release 1 is refused at `PolicyNV`, and release 2 still unseals. Then `tpm2_nvundefine` and `tpm2_nvdefine` with the empty owner auth and the provisioned attributes and size, and `tpm2_nvsetbits -i 0x0`, give an index with the provisioned name, under which release 1's signed policy unseals the sealed key; the test compares only its SHA-256. The test is named for that outcome, which is expected on today's design, so it fails once a fix makes the replay refused. It skips unless swtpm and tpm2-tools are on the PATH, except under `model/ci.py`, where it fails without them; the `model` job installs both.

[`tests/model/test_replay_a02.py`](../tests/model/test_replay_a02.py) translates [`fixtures/a02-trace.json`](../tests/model/fixtures/a02-trace.json), TLC's `Boot.cfg` counterexample, checks its actions against `A02`, written by hand, and under `model/ci.py` that TLC's trace of that run still gives them. On swtpm, provisioned for the PCRs that one digest per PCR gives and release 2, it plays U-Boot and the initramfs, which unseals and caps. As userspace it then checks TC-05b's baseline: a new session is refused at `PolicyAuthorize`. Then the TPM alone resets, userspace replays the measurements, and the key unseals a second time; the test is named for that outcome, expected on today's design for an attacker who can reset the TPM. It skips and fails as the A-01 replay does.

**Finite epochs.** The TPM's bit field has 64 bits; this model has bits 1 to `MaxEpoch` = 3 and releases at epochs 1 and 2, so a bit lies above every release. No command treats one bit differently from another, so in this model one commit above one older release shows the behavior; larger epochs are not checked. A bit above every release only denies every policy, which is availability, and this model does not check it.

**Abstract name.** The nameAlg is SHA-256 throughout. The TPM names an index nameAlg ‖ H(TPMS_NV_PUBLIC): index handle, nameAlg, attributes with `TPMA_NV_WRITTEN`, authPolicy and dataSize. `tools/approve_policy.py` computes the same, and the VE-07 harness compares it with swtpm's at provisioning. In this model the name is the tuple of those fields, so H is taken as collision-free and two indexes share a name exactly when their public areas match. A redefinition with other attributes or authPolicy therefore gets another name, its `PolicyNV` digest matches no signed policy, and `PolicyAuthorize` refuses it; with `NV_DefineSpace` barred from the provisioned attributes, TLC finds `NoOldReleaseUnseals` holding, while `EpochMonotonic` still fails: the epoch is reset, but no release can use the new index (a local check, not a configuration). Modeling the name was clear, so the proposal's no-go condition does not apply.

**Abstract policy digests.** A digest is the tuple of what the TPM hashes into it, and every digest equal to no signed approved policy is one value, `Other`: `PolicyAuthorize` compares digests exactly and only K-CC-POL, on the MSS, signs, so in this model all such digests behave alike. PCR stages are out of scope, so an approved policy is `PolicyNV` alone. The invariant records whose approved policy released the keys (`via`, which the TPM does not keep), not which program asked. One session exists at a time, and `Commit` ends it: the commit runs in a later boot, of the newer release, so in this model no session of an older boot spans it.

**An attacker that knows only empty owner auth.** Any caller may issue every command above. Owner authorization is usable only while it is `"empty"`, as in P2; a set value is unknown to the attacker in this model, and only the legitimate `Commit` holds it. Each index's own authValue is empty, so `authread` and `authwrite` need no secret. Platform authorization is not modeled, so in this model `POLICY_DELETE`, which needs it, cannot be defined.
